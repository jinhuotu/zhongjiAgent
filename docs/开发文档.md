## 1. 一句话结论

主 API（`zhongji-api` :8000）已具备：**JWT 登录**、**用户/角色管理**、**知识库 RAG**、**LLM/Embedding 模型配置**、**提示词管理**、**MCP 工具**、**场景智能体**、**AI 对话 SSE（服务端 Redis 上下文）**、**热配置**。  
对话异步落库依赖独立进程 **`zhongji-chat-worker`**（本地可用 **`zhongji-dev` 一键起两者**）。  
前端（`zhongjivueweb`）已直连：登录、AI 对话、场景智能体、知识库、模型/提示词/MCP 管理、用户管理、**AI 报告**、数据治理、生产 SCADA；其余约大量业务页仍 mock。

本地验证：

```powershell
poetry run python -m alembic upgrade head   # 迁移 0001～0022（含工作流 + AI 报告绑定）
poetry run python scripts/seed_admin.py
poetry run python scripts/seed_agents.py    # 可选：示例场景智能体
poetry run python scripts/seed_mcp_utility.py  # 可选：时间/天气 MCP 工具
poetry run python scripts/seed_production_scada.py  # 生产侧三系统模拟数据
docker compose -f deploy/docker-compose.yml up -d redis qdrant
poetry run zhongji-dev                      # 或分别起 api + chat-worker
# 前端 zhongjivueweb .env：VITE_API_BASE_URL=http://127.0.0.1:8000
```

### 3.4 主业务 API（`apps/api` :8000）

| PATCH/DELETE | `/{role_id}` | 更新 / 删除 |

#### 知识库 `/api/v1/knowledge`（Bearer）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/bases` | 列表 / 创建 |
| GET/PATCH/DELETE | `/bases/{base_id}` | 详情 / 更新 / 删除 |

#### AI `/api/v1/ai`（Bearer）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/status` | LLM / Embedding 就绪 |
| GET/POST | `/sessions` | 会话列表 / 创建 |
| GET/PATCH/DELETE | `/sessions/{id}` | 详情（MySQL+Redis 合并）/ 更新 / 删除 |
| POST | `/sessions/{id}/summarize-title` | LLM 标题 |
| POST | `/chat` | **SSE**：`refs` → `delta`/`tool`* → `done`/`error`；Body 以 `sessionId`+`content` 为主；可选 `promptId` / `knowledgeBaseIds` / **`agentId`** |
| POST | `/chat/related` | 相关追问 |
| GET | `/reports/types` | 报告类型元数据 |
| GET | `/reports` | 当前用户报告历史 |
| GET/DELETE | `/reports/{id}` | 详情（含正文）/ 删除 |
| POST | `/reports/generate` | **SSE**：`meta` → `delta` → `done`/`error`；Body `{ type, furnaceId, mode }` |

对话链路要点：同步路径写 Redis List + Stream；**不写** MySQL；上下文由服务端组装；Worker 最终一致归档。  
若传有效 **`agentId`**：服务端以智能体配置覆盖 `mode` / `promptId` / `knowledgeBaseIds` / MCP 工具策略（`toolsEnabled` + 可选白名单）；`refs`/`done` 可带回 `agentId`/`agentName`。

#### MCP `/api/v1/mcp-servers`（Admin 为主；前端菜单「工具管理」）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `` | 列表 / 创建 |

| POST | `/{id}/health`、`/{id}/refresh-tools` | 探活 / 刷新工具 |

对话侧消费：全局 `enabled` 的 server ∩ tool；智能体可再叠加白名单或关闭工具。

内置示例 MCP（中国时间 + 天气，stdio）：

```powershell
poetry run python scripts/seed_mcp_utility.py
```

- 脚本：`scripts/mcp_utility_server.py`

## 6. 关键实现细节

### 6.1 统一响应

```json
{ "code": 0, "msg": "ok", "data": {} }
```

HTTP 状态与业务 `code` 分离（如 401 + `code=40100`）。部分接口为兼容前端会顶层镜像 `items` 等字段。

### 6.2 鉴权

```
login → access + refresh + user
业务路由 → CurrentUser / AdminUser（is_superuser 或 role admin）
```

注意：Refresh 不查库；无全局默认鉴权中间件；新路由需自行注入依赖。

### 6.3 数据库与中间件地址

- 应用与 Alembic 均读 `DATABASE_URL`。  
- Redis 默认：`REDIS_URL=redis://127.0.0.1:16379/0`（避开本机占用的 6379）。  
- Qdrant 默认 HTTP `6333`。

### 6.4 AI Chat SSE

请求体（现行约定）：

```json
{ "sessionId": "<uuid>", "content": "本轮用户问题", "mode": "fast" }
```

前端**不再**传完整 `messages` 历史。事件：`refs` → `delta`* → `done` | `error`。

详细 Redis Key、裁剪、限流、TTL 见 [`chat-memory.md`](./chat-memory.md)。

### 6.5 服务进程：为何两命令 + 本地融合

| 命令 | 职责 |
|---|---|
| `poetry run zhongji-api` | HTTP：鉴权、业务、SSE；写 Redis List+Stream |
| `poetry run zhongji-chat-worker` | 消费 Stream→MySQL；定时 TTL 扫库兜底 |
| `poetry run zhongji-dev` | **本地便捷**：同时拉起上述两个**子进程**；Ctrl+C 一起停 |

**不能也不应真正「融成单进程」的原因：**

1. API 与归档解耦：一边挂了不影响另一边重启/扩容。  
2. Worker 含阻塞消费循环 + 定时任务，不宜塞进 Uvicorn worker。  
3. Docker / 生产应对应两个容器（compose：`chat-consumer-worker` + profile `workers`）。

因此：`zhongji-dev` 只是本地「一条命令起两个进程」，架构上仍是双进程。

日常联调前端（含智能问答持久化）：**MySQL + Redis + Qdrant + `zhongji-dev`（或 api+worker）**。

其他占位：

| 命令 | 端口 |
|---|---|
| `zhongji-ai` | 8001 |
| `zhongji-ingest` | 8002 |
| `zhongji-model` | 8003 |

### 知识库 / 模型

见 Swagger `/docs`；前缀分别为 `/api/v1/knowledge`、`/api/v1/models`。

**检索精度调参（环境变量，对应 `packages/common/config.py`）：**

| 变量 | 默认 | 说明 |
|---|---|---|
| `KB_CHUNK_SIZE` | 800 | 分块大小；手册建议 600～1000 |
| `KB_CHUNK_OVERLAP` | 120 | 分块重叠 |
| `KB_SEARCH_TOP_K` | 5 | 最终返回条数 |
| `KB_SEARCH_MIN_SCORE` | 0.0 | 向量分阈值；可试 `0.25`～`0.35` 滤弱相关（视 Embedding 分数分布） |
| `KB_SEARCH_CANDIDATE_MULTIPLIER` | 4 | 先多召回再关键词重排 |
| `KB_SEARCH_KEYWORD_WEIGHT` | 0.4 | 混合分中关键词权重；专名查询可调到 `0.45`～`0.55` |

分块会尽量按 `8.3 xxx` / `第九章` 等标题切开。改分块参数后需**删除资料并重新上传**；仅改检索权重/阈值重启 API 即可。
