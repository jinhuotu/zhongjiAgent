# 生产部署手册（阿里云 ECS 同机三套站点）

| 项 | 内容 |
|---|---|
| 文档版本 | V2.0 |
| 编制依据 | 2026-09 华东 1（杭州）ECS 实装：优祺 + 中机六院 + 伟泰同机部署与排障 |
| 参考规格 | `ecs.u2a-c1m2.xlarge`、4 核 8G、40GB ESSD、5Mbps、Ubuntu 24.04、x86_64（AMD，非倚天 ARM） |
| 实装主机 | 公网 IP 示例 `47.110.79.248`（下文写作 `公网IP`）；主机名 `iZbp1gqqt6klh7v2htrhbbZ` |
| 代码目录 | `/opt/apps/{youqi,zhongji,weitai}/{backend,web}` |

> **相对 V1.1 的变更：** 由「单套中机 / 轻量机」改为「一台 ECS 部署三套互不相同的产品」。优祺、中机、伟泰 **仓库与启动方式均不同**，禁止互相套用 systemd 命令。基础设施只起一份 MySQL / Redis / Qdrant，另加伟泰专用 OnlyOffice 容器。

登录服务器后先确认主机，避免操作到旧机（旧机上已有跑了数周的 `zhongji-*` / `youqi-api:8091`）：

```bash
hostname
curl -s ifconfig.me; echo
```

## 1. 三套工程对照（必读）

| | 优祺智能 | 中机六院 | 伟泰 |
|---|---|---|---|
| 后端仓库 | `https://github.com/jinhuotu/youqiAgent.git` | `https://github.com/jinhuotu/zhongjiAgent.git` | `https://github.com/jinhuotu/weitaiAgent.git` |
| 前端仓库 | `https://github.com/jinhuotu/youqiAgent-web.git` | `https://github.com/jinhuotu/zhongjivueweb.git` | `https://github.com/jinhuotu/weitaiAgentui.git` |
| 产品形态 | 内部运维台（`X-Service-Token`，无登录页） | 完整业务平台（JWT 登录） | 中机精简分叉 + 投标在线 Word |
| 启动入口 | `.venv/bin/uvicorn app.main:app` | `.venv/bin/zhongji-api` | `.venv/bin/weitai-api` |
| systemd | **`youqi-agent` 一个进程** | `zhongji-api` + `zhongji-chat-worker` | `weitai-api` + `weitai-chat-worker` |
| 种子账号 | **无** `seed_admin.py` | `scripts/seed_admin.py` | `scripts/seed_admin.py` |
| 向量库 | **Chroma**（`./data/chroma`） | Qdrant collection `zhongji_knowledge` | Qdrant collection `weitai_knowledge` |
| 本机 API | `127.0.0.1:8002` | `127.0.0.1:8001` | `0.0.0.0:8100`（OnlyOffice 回调需要；安全组勿放行 8100） |
| Nginx | **`:81`** | **`:80`** | **`:82`** |
| Redis 逻辑库 | `/0` | `/2` | `/3` |
| MySQL 库 | `db_youqi`（或历史名 `agent_ai`） | `zhongji_agent` | `weitai_agent` |
| 额外容器 | 无 | 无 | **`onlyoffice/documentserver:8.2.2` → 宿主机 8082** |

**不要做的事：**

- 不要给优祺写 `zhongji-api` / `zhongji-chat-worker`（会 `203/EXEC`）。
- 不要给优祺跑 `scripts/seed_admin.py`（文件不存在）。
- 不要三套各起一份 MySQL / Redis / Qdrant（8G / 40G 会爆）。
- 不要启动中机的 `zhongji-ai` / `ingest` / `model` / `zhongji-dev`（端口与优祺冲突且占内存）。
- 不要用伟泰 `infra/docker-compose.yml` 全量 `up`（会映射 13306 / 26379 / 16333，与现网冲突）。只起 OnlyOffice。

## 2. 目标架构

```
浏览器
  → http://公网IP/            Nginx :80   中机 dist  + 反代 127.0.0.1:8001
  → http://公网IP:81/         Nginx :81   优祺 dist  + 反代 127.0.0.1:8002
  → http://公网IP:82/         Nginx :82   伟泰 dist  + 反代 127.0.0.1:8100
  → http://公网IP:8082/       OnlyOffice（伟泰在线 Word；浏览器直连）

本机内部（安全组不要放行）：
  MySQL   127.0.0.1:3306     三个库
  Redis   127.0.0.1:6379     三个逻辑库 0 / 2 / 3
  Qdrant  127.0.0.1:6333     中机 / 伟泰各用不同 collection
  Chroma  优祺进程本地目录
  API     8001 / 8002 / 8100
```

内存建议（8G + 4G Swap）：

| 组件 | 预算 |
|---|---|
| 系统 + Nginx + Docker | ~1GB |
| MySQL（innodb 384M） | ~0.7GB |
| Redis | ~0.15GB |
| Qdrant | ~0.5GB |
| 优祺 API | ~0.2GB |
| 中机 API + Worker | ~0.5GB |
| 伟泰 API + Worker | ~0.5GB |
| OnlyOffice | **1.5GB 上限**（可后装） |

`free -h` 的 available 低于 2GB 时不要先起 OnlyOffice。

## 3. 云控制台与系统初始化（只做一次）

### 3.1 安全组

入方向放行：

| 协议 | 端口 | 用途 |
|---|---|---|
| TCP | 22 | SSH |
| TCP | 80 | 中机 |
| TCP | 81 | 优祺 |
| TCP | 82 | 伟泰 |
| TCP | 443 | 以后 HTTPS |
| TCP | 8082 | OnlyOffice（不上在线 Word 可不开） |

**不要**放行 3306 / 6379 / 6333 / 8001 / 8002 / 8100。  
只开系统 `ufw`、控制台未放行 → 外网超时；浏览器若走 Clash 等代理，非标准端口常显示 **HTTP 502**（不是 Nginx 的 502）。

### 3.2 系统

Ubuntu 24.04 自带 Python 3.12，不必装 deadsnakes。

```bash
apt update && apt upgrade -y
apt install -y curl wget git vim ufw htop unzip ca-certificates gnupg \
  python3.12 python3.12-venv python3.12-dev build-essential libssl-dev nginx
timedatectl set-timezone Asia/Shanghai

fallocate -l 4G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
grep -q swapfile /etc/fstab || echo '/swapfile none swap sw 0 0' >> /etc/fstab

ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw allow 81/tcp
ufw allow 82/tcp
ufw allow 8082/tcp
ufw --force enable

mkdir -p /opt/apps/{youqi,zhongji,weitai,infra}
uname -m    # 应为 x86_64
```

### 3.3 Docker / Poetry / Node

```bash
curl -fsSL https://get.docker.com | sh
usermod -aG docker "$USER"
# 重新登录 SSH 后再继续

mkdir -p /etc/docker
cat >/etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1ms.run"
  ]
}
EOF
# 更稳：把阿里云容器镜像加速器地址放到 registry-mirrors 最前
systemctl daemon-reload
systemctl restart docker

curl -sSL https://install.python-poetry.org | python3 -
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
poetry config virtualenvs.in-project true

curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs
npm config set registry https://registry.npmmirror.com
```

## 4. 共享基础设施

只起 **一份** MySQL / Redis / Qdrant。优祺用 Chroma，不占用 Qdrant；中机和伟泰共用 Qdrant 进程、不同 collection。

`/opt/apps/infra/docker-compose.yml`：

```yaml
services:
  mysql:
    image: mysql:8.0
    container_name: apps-mysql
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: "换成强密码_Root"
    ports:
      - "127.0.0.1:3306:3306"
    volumes:
      - mysql_data:/var/lib/mysql
    command:
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_unicode_ci
      - --innodb-buffer-pool-size=384M
      - --performance-schema=OFF
    mem_limit: 768m

  redis:
    image: redis:7-alpine
    container_name: apps-redis
    restart: unless-stopped
    ports:
      - "127.0.0.1:6379:6379"
    volumes:
      - redis_data:/data
    command: ["redis-server", "--maxmemory", "128mb", "--maxmemory-policy", "allkeys-lru"]
    mem_limit: 192m

  qdrant:
    image: qdrant/qdrant:v1.12.5
    container_name: apps-qdrant
    restart: unless-stopped
    ports:
      - "127.0.0.1:6333:6333"
      - "127.0.0.1:6334:6334"
    volumes:
      - qdrant_data:/qdrant/storage
    mem_limit: 768m

volumes:
  mysql_data:
  redis_data:
  qdrant_data:
```

```bash
cd /opt/apps/infra
docker compose up -d
docker exec -it apps-mysql mysql -uroot -p
```

```sql
CREATE DATABASE IF NOT EXISTS db_youqi CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE DATABASE IF NOT EXISTS zhongji_agent CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE DATABASE IF NOT EXISTS weitai_agent CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE USER IF NOT EXISTS 'u_youqi'@'%' IDENTIFIED BY '换成强密码1';
CREATE USER IF NOT EXISTS 'u_zhongji'@'%' IDENTIFIED BY '换成强密码2';
CREATE USER IF NOT EXISTS 'weitai'@'%' IDENTIFIED BY 'WeitaiDb_ChangeMe1';

GRANT ALL ON db_youqi.* TO 'u_youqi'@'%';
GRANT ALL ON zhongji_agent.* TO 'u_zhongji'@'%';
GRANT ALL ON weitai_agent.* TO 'weitai'@'%';
FLUSH PRIVILEGES;
```

从宿主机连 Docker MySQL 时，容器里看到的客户端是 `172.18.0.1` 一类网桥地址，用户必须是 `'xxx'@'%'`，不能只用 `'xxx'@'localhost'`。密码尽量不要含 `@` `#` `:`，以免 `DATABASE_URL` 被拆错。

若机器上已有监听 `127.0.0.1:3306` 的 MySQL 容器，**不要再起一份**，在现有实例里执行上面的 `CREATE DATABASE` 即可。

## 5. 优祺

仓库自带 `DEPLOY.md` / `docker/DOCKER.md`。同机已有共享库时，用 Poetry + systemd，**不要**再起官方 Compose 的 `youqi-api:8091`（会和第二套优祺打架）。

```bash
cd /opt/apps/youqi
git clone --depth 1 https://github.com/jinhuotu/youqiAgent.git backend
git clone --depth 1 https://github.com/jinhuotu/youqiAgent-web.git web
```

`.env` 要点（库名以实际为准，须先 `CREATE DATABASE`，Alembic **不会**自动建库）：

```bash
ENV=production
SERVER_HOST=127.0.0.1
SERVER_PORT=8002
CORS_ORIGINS=http://公网IP:81
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=u_youqi
MYSQL_PASSWORD=换成强密码1
MYSQL_DATABASE=db_youqi
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_DB=0
CHROMA_PERSIST_PATH=./data/chroma
UPLOAD_ROOT=./data/uploads
INTERNAL_SERVICE_TOKENS=用_openssl_rand_-hex_32_生成
ENCRYPTION_KEY=poetry_install后_Fernet.generate_key
```

```bash
cd /opt/apps/youqi/backend
mkdir -p data/chroma data/uploads
poetry env use python3.12
poetry source add --priority=primary aliyun https://mirrors.aliyun.com/pypi/simple/ 2>/dev/null || true
export POETRY_REQUESTS_TIMEOUT=600
poetry install --only main
poetry run alembic upgrade head
```

`/etc/systemd/system/youqi-agent.service`：

```ini
[Unit]
Description=youqiAgent AI Service
After=network.target docker.service
Requires=docker.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/apps/youqi/backend
EnvironmentFile=/opt/apps/youqi/backend/.env
ExecStart=/opt/apps/youqi/backend/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8002 --workers 1
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

**没有** chat-worker。知识库任务在 API 进程内用 Redis 队列。

```bash
systemctl daemon-reload
systemctl enable --now youqi-agent
curl -s http://127.0.0.1:8002/health
# 期望 {"status":"ok","version":"1.0.0"}
```

前端：

```bash
cd /opt/apps/youqi/web
cat > .env.production <<EOF
VITE_API_BASE_URL=http://公网IP:81
EOF
npm install && npm run build
ls dist/index.html
rm -rf node_modules
```

运维台「连接设置」：

| 项 | 值 |
|---|---|
| API Base URL | `http://公网IP:81`（**不要** `:8000` / `:8002`） |
| Service Token | 与 `INTERNAL_SERVICE_TOKENS` 完全一致 |
| User Id | 如 `001` |
| Role | 管理用 `admin` |

留空 Base URL 表示同源，也可。直连 `:8002` 会超时：API 绑在 `127.0.0.1`，安全组也不放行该端口。此时总览里 MySQL/Redis/Chroma「异常」只是接口没调到，不代表组件挂了。

重启：`systemctl restart youqi-agent`。

## 6. 中机六院

```bash
cd /opt/apps/zhongji
git clone --depth 1 https://github.com/jinhuotu/zhongjiAgent.git backend
git clone --depth 1 https://github.com/jinhuotu/zhongjivueweb.git web
```

`.env` 要点：

```bash
APP_ENV=prod
DEBUG=false
CORS_ORIGINS=http://公网IP
API_HOST=127.0.0.1
API_PORT=8001
DATABASE_URL=mysql+asyncmy://u_zhongji:换成强密码2@127.0.0.1:3306/zhongji_agent?charset=utf8mb4
REDIS_URL=redis://127.0.0.1:6379/2
JWT_SECRET_KEY=openssl_rand_-hex_32
QDRANT_URL=http://127.0.0.1:6333
QDRANT_COLLECTION=zhongji_knowledge
CHAT_MEMORY_COLLECTION=zhongji_chat_memory
STORAGE_ROOT=./storage
```

`REDIS_URL` 末尾是 **库号 0～15**，禁止写成 `/6379`（Worker 会报 `DB index is out of range` 并 `auto-restart`）。  
`.env.example` 默认 Redis 是 **16379**，生产共享栈必须改成 **6379**。

```bash
cd /opt/apps/zhongji/backend
poetry env use python3.12
export POETRY_REQUESTS_TIMEOUT=600
poetry install --no-interaction
mkdir -p storage
poetry run python -m alembic upgrade head
poetry run python scripts/seed_admin.py
# 默认 admin / Admin@123456 ，上线改密
```

**systemd 不要写 `EnvironmentFile=`。** systemd 解析 `.env` 与 Pydantic 不同：前台 `poetry run zhongji-api` 听 8001，`systemctl` 却落到代码默认 **0.0.0.0:8800**，Nginx 反代 8001 就会 502。

```ini
[Unit]
Description=Zhongji FastAPI
After=network.target docker.service
Requires=docker.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/apps/zhongji/backend
Environment=PATH=/opt/apps/zhongji/backend/.venv/bin:/usr/bin
ExecStart=/opt/apps/zhongji/backend/.venv/bin/zhongji-api
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Worker 同结构，`ExecStart=.../zhongji-chat-worker`，unit 名 `zhongji-chat-worker.service`。

```bash
systemctl daemon-reload
systemctl enable --now zhongji-api zhongji-chat-worker
ss -lntp | grep -E ':8001|:8002'
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8001/docs
```

`ss` 里中机必须是 **8001**，且进程为 `zhongji-api`。若仍在 8000：检查是否还有 `EnvironmentFile`、是否 `DEBUG=true` 触发 reload、`.env` 是否有重复的 `API_PORT`。

前端：

```bash
cd /opt/apps/zhongji/web
cat > .env.production <<EOF
VITE_API_BASE_URL=http://公网IP
EOF
npm install && npm run build
rm -rf node_modules
```

登录：`http://公网IP/login`。Network 必须是 `http://公网IP/api/v1/auth/login`（无 `:8001`）。

## 7. 伟泰

### 7.1 后端

```bash
cd /opt/apps/weitai
git clone --depth 1 https://github.com/jinhuotu/weitaiAgent.git backend
git clone --depth 1 https://github.com/jinhuotu/weitaiAgentui.git web
```

`.env` 不要照抄仓库里的 13306 / 26379 / 16333：

```bash
APP_ENV=prod
DEBUG=false
CORS_ORIGINS=http://公网IP:82
API_HOST=0.0.0.0
API_PORT=8100
DATABASE_URL=mysql+asyncmy://weitai:WeitaiDb_ChangeMe1@127.0.0.1:3306/weitai_agent?charset=utf8mb4
REDIS_URL=redis://127.0.0.1:6379/3
JWT_SECRET_KEY=openssl_rand_-hex_32
QDRANT_URL=http://127.0.0.1:6333
QDRANT_COLLECTION=weitai_knowledge
STORAGE_ROOT=./storage
ONLYOFFICE_DOCUMENT_SERVER_URL=http://公网IP:8082
ONLYOFFICE_JWT_SECRET=与容器 JWT_SECRET 完全一致
ONLYOFFICE_PUBLIC_API_BASE=http://host.docker.internal:8100
```

`1045 Access denied for user 'weitai'@'172.18.0.1'`：`.env` 用户/密码/端口与 MySQL 实际用户不一致，或用户不是 `'weitai'@'%'`。先 `alembic upgrade head` 再 `seed_admin.py`。

systemd 同样 **不要** `EnvironmentFile`，工作目录 `/opt/apps/weitai/backend`，`ExecStart` 为 `weitai-api` / `weitai-chat-worker`。

### 7.2 OnlyOffice（多出来的镜像）

镜像 `onlyoffice/documentserver:8.2.2`，宿主机 **8082 → 容器 80**。Linux 必须加 `host.docker.internal`，容器才能回调本机 8100。

```bash
OO_SECRET=$(openssl rand -hex 24)
echo "$OO_SECRET"   # 写入 .env 的 ONLYOFFICE_JWT_SECRET 与下面 JWT_SECRET

docker run -d --name weitai-onlyoffice --restart unless-stopped \
  -p 8082:80 \
  --memory 1536m \
  --add-host=host.docker.internal:host-gateway \
  -e JWT_ENABLED=true \
  -e JWT_SECRET="$OO_SECRET" \
  -v onlyoffice_data:/var/www/onlyoffice/Data \
  -v onlyoffice_logs:/var/log/onlyoffice \
  onlyoffice/documentserver:8.2.2
```

首次启动 1～3 分钟。`curl -sI http://127.0.0.1:8082/` 应有 HTTP 响应。  
内存不够可先不上 OnlyOffice，登录与其它功能仍可用，在线 Word 不可用。

`API_HOST=0.0.0.0` 仅供容器回调；安全组不要放行 8100。

### 7.3 前端构建

`package.json` 的 `build` 是 `vue-tsc -b && vite build`。若 `TendersView.vue` 缺少 `previewHintsOpen` / `moneyLabel`、`TenderDocEditor.vue` 未使用 `lastBootHeight`、`WorkflowEditorView.vue` 的 `nodeTypes` 与 Vue Flow 类型不兼容，**vue-tsc 会拦截，dist 不会生成**。

临时上线：

```bash
cd /opt/apps/weitai/web
cat > .env.production <<EOF
VITE_API_BASE_URL=http://公网IP:82
EOF
npm install
npx vite build
```

## 8. Nginx

三个独立 `server`，互不改端口。删除 default 以免抢 80。

`/etc/nginx/sites-available/zhongji`：`listen 80`，`root /opt/apps/zhongji/web/dist`，`location /api/` → `http://127.0.0.1:8001`（SSE：`proxy_buffering off`，超时 3600s）。

`/etc/nginx/sites-available/youqi`：`listen 81`，`root /opt/apps/youqi/web/dist`，`/api/` 与 `/health` `/ready` `/docs` → `http://127.0.0.1:8002`。

`/etc/nginx/sites-available/weitai`：`listen 82`，`root /opt/apps/weitai/web/dist`，`client_max_body_size 200m`，`/api/` → `http://127.0.0.1:8100`。

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
location /api/ {
    proxy_pass http://127.0.0.1:8001;   # 优祺改 8002，伟泰改 8100
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_read_timeout 3600s;
}
```

`proxy_pass` 的端口必须与 `ss -lntp` 里对应 API **正在监听**的端口一致。

```bash
ln -sf /etc/nginx/sites-available/zhongji /etc/nginx/sites-enabled/
ln -sf /etc/nginx/sites-available/youqi /etc/nginx/sites-enabled/
ln -sf /etc/nginx/sites-available/weitai /etc/nginx/sites-enabled/
rm -f /etc/nginx/sites-enabled/default
nginx -t && systemctl reload nginx
```

有域名后用三个子域名 + Certbot 全部走 80/443，可关掉 81/82。改 `CORS_ORIGINS` 与 `VITE_API_BASE_URL` 后必须 **重建前端**。

## 9. 外网地址

| 站点 | URL | 说明 |
|---|---|---|
| 中机 | `http://公网IP/login` | `admin` / `Admin@123456` |
| 优祺 | `http://公网IP:81/` | 连接设置填 `:81` + Token |
| 伟泰 | `http://公网IP:82/`（常见为 `/login`） | `admin` / `Admin@123456` |
| OnlyOffice | 页面内打开文档；资源来自 `:8082` | JWT 与 `.env` 必须一致 |

本机验收：

## 11. 实战排障

| 现象 | 原因 | 处理 |
|---|---|---|
| `203/EXEC` | ExecStart 用了另一套产品的命令名 | 优祺用 uvicorn；中机 `zhongji-api`；伟泰 `weitai-api` |
| 优祺 Worker 找不到 | 优祺没有该进程 | 不要启用 `youqi-chat-worker` |
| Alembic `1049 Unknown database` | 库未创建 | `CREATE DATABASE`，与 `DATABASE_URL` 库名一致 |
| `1045 Access denied ...@'172.18.0.1'` | 用户/密码不对或 host 不是 `%` | 重建 `'user'@'%'`，对齐 `.env` |
| 中机 Worker `auto-restart` | Redis URL 仍是 16379，或写成 `/6379` | `redis://127.0.0.1:6379/2` |
| 本机 `curl 127.0.0.1:81/` 200，浏览器 502 | 安全组未放 81，或 Clash 代理访问非标端口失败 | 安全组放行；代理直连；可改 80 |
| 中机页面 200、登录 502 | Nginx 反代 8001，API 听在 8000 | `ss` 对齐 `proxy_pass`；修 systemd 去掉 EnvironmentFile |
| `poetry run` 8001、`systemctl` 8000 | EnvironmentFile 覆盖/未加载 `.env` | 去掉 EnvironmentFile，靠 WorkingDirectory |
| 优祺连接 timeout | Base URL 填了 `:8002` | 改为与地址栏相同的 `:81` |
| 伟祺 `npm run build` 12 个 TS 错误 | vue-tsc 拦截 | 先 `npx vite build`，再修源码 |
| OnlyOffice 白屏 | JWT 不一致，或 API 只绑 127.0.0.1 | 对齐 JWT；`API_HOST=0.0.0.0` + `host.docker.internal` |
| 外网超时、本机 curl 通 | 安全组未放行对应端口 | ECS 安全组 ≠ ufw |
| 两台主机命令混贴 | 旧机 `iZbp182yj2...` 与新机 `iZbp1gqqt6...` | 先 `hostname` / `ifconfig.me` |

日志：

```bash
journalctl -u zhongji-api -n 80 --no-pager
journalctl -u zhongji-chat-worker -n 80 --no-pager
journalctl -u weitai-api -n 80 --no-pager
```

## 12. 推荐实施顺序

1. 安全组 22/80/81/82 → SSH → Swap → Docker 加速 → Python/Node  
2. 共享 MySQL/Redis/Qdrant，建三个库、三个 `'user'@'%'`  
3. 优祺：alembic → `youqi-agent:8002` → 前端 build → Nginx 81 → 连接设置填 `:81`  
4. 中机：alembic → seed_admin → systemd **无 EnvironmentFile** → 确认听 8001 → 前端 build → Nginx 80  
5. 伟泰：对齐 MySQL 账号 → alembic → seed → API 8100 → `npx vite build` → Nginx 82  
6. `free -h` 够再起 OnlyOffice，对 JWT 与两个 URL  
7. 浏览器验收三套；中机/伟泰改默认密码；优祺保管 Token
