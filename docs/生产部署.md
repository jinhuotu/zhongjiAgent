# 生产部署手册（轻量云主机）

| 项 | 内容 |
|---|---|
| 文档版本 | V1.0 |
| 编制依据 | 2026-08 阿里云轻量机实装与排障 |
| 后端工程 | `zhongjiAgent`（Poetry / FastAPI） |
| 前端工程 | `aizhongjiweb`（Next.js / pnpm） |
| 参考规格 | 2 核 4G、约 40GB 盘、5Mbps、Ubuntu 22.04/24.04、公网 IP |

---

## 1. 架构说明

```
浏览器
  → http(s)://公网IP或域名/          Nginx :80/:443
       ├─ /          → Next.js  127.0.0.1:5000
       └─ /api/      → FastAPI  127.0.0.1:8000  （含 SSE）

本机仅内部访问：
  MySQL 127.0.0.1:3306
  Redis 127.0.0.1:6379
  Qdrant 127.0.0.1:6333
  API / 前端 / Worker 不直接对公网暴露（除调试外勿开 8000/5000）
```

| 进程 | 管理方式 | 说明 |
|---|---|---|
| MySQL / Redis / Qdrant | Docker Compose | 基础设施 |
| `zhongji-api` | systemd | 主 API |
| `zhongji-chat-worker` | systemd | 对话 Stream 归档（生产必须单独跑，禁止用 `zhongji-dev`） |
| `zhongji-web` | systemd | 前端 `pnpm start` |
| Nginx | systemd | 唯一公网入口 |

**2C4G 注意：** 内存紧张，务必加 **2～4GB Swap**；限制 MySQL `innodb-buffer-pool-size`；不要同机再起 `zhongji-ai/ingest/model` 占位进程。

## 2. 服务器初始化

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y curl wget git vim ufw htop unzip ca-certificates gnupg lsb-release

sudo timedatectl set-timezone Asia/Shanghai

# Swap（强烈建议）
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# 防火墙：只放行 SSH / HTTP / HTTPS
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
```

**云控制台（必做）：** 轻量「防火墙」或安全组放行 **TCP 80、443、22**。  
只开系统 `ufw`、控制台未放行 → 外网会出现 `ERR_CONNECTION_CLOSED` / 无法访问。

目录约定：

```bash
sudo mkdir -p /opt/zhongji
sudo chown -R $USER:$USER /opt/zhongji
```

### 3.2 国内 Docker 镜像加速（必配）

国内主机拉 Docker Hub 常出现：

```text
dial tcp ... registry-1.docker.io:443: i/o timeout
```

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.xuanyuan.me",
    "https://docker.m.daocloud.io"
  ]
}
EOF
sudo systemctl daemon-reload
sudo systemctl restart docker
docker info | grep -A5 "Registry Mirrors"
```

更稳妥：登录 [阿里云容器镜像服务](https://cr.console.aliyun.com/cn-hangzhou/instances/mirrors) 复制个人加速器地址写入 `registry-mirrors`。

备选：本机 `docker pull` + `docker save`，上传服务器 `docker load`。

## 5. 基础设施（MySQL / Redis / Qdrant）

```bash
mkdir -p /opt/zhongji/infra
cd /opt/zhongji/infra
```

创建 `docker-compose.yml`（端口仅绑定本机，勿对公网暴露）：

```yaml
services:
  mysql:
    image: mysql:8.0
    container_name: zhongji-mysql
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: "换成强密码_Root"
      MYSQL_DATABASE: zhongji_agent
      MYSQL_USER: zhongji
      MYSQL_PASSWORD: "换成强密码_User"
    ports:
      - "127.0.0.1:3306:3306"
    volumes:
      - mysql_data:/var/lib/mysql
    command:
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_unicode_ci
      - --innodb-buffer-pool-size=256M
      - --performance-schema=OFF
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "127.0.0.1", "-uroot", "-p换成强密码_Root"]
      interval: 10s
      timeout: 5s
      retries: 10

  redis:
    image: redis:7-alpine
    container_name: zhongji-redis
    restart: unless-stopped
    ports:
      - "127.0.0.1:6379:6379"
    volumes:
      - redis_data:/data
    command: ["redis-server", "--maxmemory", "128mb", "--maxmemory-policy", "allkeys-lru"]
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 3s
      retries: 10

  qdrant:
    image: qdrant/qdrant:v1.12.5
    container_name: zhongji-qdrant
    restart: unless-stopped
    ports:
      - "127.0.0.1:6333:6333"
      - "127.0.0.1:6334:6334"
    volumes:
      - qdrant_data:/qdrant/storage

volumes:
  mysql_data:
  redis_data:
  qdrant_data:
```

```bash
docker compose up -d
docker compose ps
```

> 开发用 `deploy/docker-compose.yml` 里 Redis 宿主端口是 **16379**；生产建议 **6379**，并保证 `.env` 与之一致。

### 6.1 Poetry 国内源（必配）

否则安装 `numpy`/`onnxruntime` 等易超时：



### 6.2 安装与配置

```bash
cd /opt/zhongji/zhongjiAgent
cp .env.example .env
nano .env
```

生产 `.env` 关键项（密码、域名按实际修改）：

```bash
APP_NAME=zhongji-agent
APP_ENV=prod
DEBUG=false
API_PREFIX=/api/v1
CORS_ORIGINS=http://你的公网IP
# 有 HTTPS 域名时改为：https://你的域名

API_HOST=127.0.0.1
API_PORT=8000

MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=zhongji
MYSQL_PASSWORD=换成强密码_User
MYSQL_DATABASE=zhongji_agent
DATABASE_URL=mysql+asyncmy://zhongji:换成强密码_User@127.0.0.1:3306/zhongji_agent?charset=utf8mb4

# 注意：格式 redis://主机:端口/数据库编号 ；末尾必须是 /0～/15，不要写成 /6379 或 /16379
REDIS_URL=redis://127.0.0.1:6379/0

JWT_SECRET_KEY=用_openssl_rand_-hex_32_生成
JWT_ALGORITHM=HS256
JWT_ACCESS_TOKEN_EXPIRE_MINUTES=30
JWT_REFRESH_TOKEN_EXPIRE_DAYS=7

STORAGE_ROOT=./storage
QDRANT_URL=http://127.0.0.1:6333
QDRANT_COLLECTION=lujing_knowledge
```

```bash
poetry config virtualenvs.in-project true
poetry env use python3.12
POETRY_REQUESTS_TIMEOUT=600 poetry install --no-interaction

mkdir -p storage
poetry run python -m alembic upgrade head
poetry run python scripts/seed_admin.py
# 默认：admin / Admin@123456  → 上线后立即改密
```

**LLM / Embedding：** 在系统「模型管理」页配置（写入 DB），不是靠 `.env` 的旧 LLM 变量。

### 6.3 systemd

先确认虚拟环境路径：`poetry env info -p`（常见为 `/opt/zhongji/zhongjiAgent/.venv`）。

`/etc/systemd/system/zhongji-api.service`：

```ini
[Unit]
Description=Zhongji FastAPI
After=network.target docker.service
Requires=docker.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/zhongji/zhongjiAgent
Environment=PATH=/opt/zhongji/zhongjiAgent/.venv/bin:/usr/bin
EnvironmentFile=/opt/zhongji/zhongjiAgent/.env
ExecStart=/opt/zhongji/zhongjiAgent/.venv/bin/zhongji-api
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

`/etc/systemd/system/zhongji-chat-worker.service`：

```ini
[Unit]
Description=Zhongji Chat Stream Worker
After=network.target docker.service
Requires=docker.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/zhongji/zhongjiAgent
Environment=PATH=/opt/zhongji/zhongjiAgent/.venv/bin:/usr/bin
EnvironmentFile=/opt/zhongji/zhongjiAgent/.env
ExecStart=/opt/zhongji/zhongjiAgent/.venv/bin/zhongji-chat-worker
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now zhongji-api zhongji-chat-worker
sudo systemctl status zhongji-api zhongji-chat-worker --no-pager
```

期望：

- API 日志：`Application startup complete`、`Uvicorn running on ...`
- Worker：`created stream group chat-archiver` / `chat stream consumer started`，且为 `active (running)`（不是 `auto-restart`）

```bash

  -H 'Content-Type: application/json' \
```

## 7. 前端部署

### 7.1 环境变量（关键）

`NEXT_PUBLIC_API_BASE_URL` 在 **`pnpm build` 时** 打进浏览器端代码。

| 写法 | 结果 |
|---|---|
| `http://公网IP`（推荐，配合 Nginx） | 浏览器请求 `http://IP/api/...`，同源走 80 |
| `http://公网IP:8000` | 跨域 + 公网常拦 8000 → 登录失败 / preflight failed |
| `https://公网IP`（无证书时） | HTTPS 连不上 →「无法连接后端服务」 |

```bash
cd /opt/zhongji/aizhongjiweb
cat > .env.production <<'EOF'
NEXT_PUBLIC_API_BASE_URL=http://你的公网IP
EOF
# 有域名且已配 HTTPS 时改为：https://你的域名
cp .env.production .env.local
```

### 7.2 构建与 systemd

```bash
pnpm install
pnpm build   # 2C 机器可能需 5～15 分钟；需存在 dist/server.js
```

`/etc/systemd/system/zhongji-web.service`：

```ini
[Unit]
Description=Zhongji Next.js Frontend
After=network.target zhongji-api.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/zhongji/aizhongjiweb
Environment=NODE_ENV=production
Environment=COZE_PROJECT_ENV=PROD
Environment=HOSTNAME=127.0.0.1
Environment=DEPLOY_RUN_PORT=5000
Environment=PORT=5000
ExecStart=/usr/bin/pnpm start
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now zhongji-web
sudo systemctl status zhongji-web --no-pager
# 日志应有：已就绪 → http://127.0.0.1:5000
```

> 改过 `NEXT_PUBLIC_*` 后必须重新 `pnpm build`，仅 `systemctl restart` 无效。

## 8. Nginx

```bash
sudo apt install -y nginx
```

`/etc/nginx/sites-available/zhongji`：

```nginx
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    server_name 你的公网IP;   # 或域名 / _

    client_max_body_size 50m;

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        # AI 对话 SSE
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }
}
```

```bash
sudo ln -sf /etc/nginx/sites-available/zhongji /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

有域名后配 HTTPS：

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d 你的域名
```

然后把前端 `NEXT_PUBLIC_API_BASE_URL`、后端 `CORS_ORIGINS` 改为 `https://域名`，**重建前端**并重启 API/Web。

## 9. 验收清单

```bash
# 服务
sudo systemctl status zhongji-api zhongji-chat-worker zhongji-web nginx --no-pager
ss -lntp | grep -E ':80|:5000|:8000'
cd /opt/zhongji/infra && docker compose ps

# 本机经 Nginx
curl -s -o /dev/null -w "web:%{http_code}\n" http://127.0.0.1/
curl -s -X POST http://127.0.0.1/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"Admin@123456"}'
```

浏览器：

1. 打开 `http://公网IP/login`，Ctrl+F5  
2. F12 → Network → 登录成功时 Request URL 必须是：  
   `http://公网IP/api/v1/auth/login`（无 `:8000`、无错误的 `https`）  
3. 进入首页；无窑炉 Excel 时可提示「暂无窑炉历史数据」，**不应**白屏崩溃  
4. 后台「模型管理」配置 LLM 后测 `/ai-chat`

**不要用地址栏 GET 打开** `/api/v1/auth/login`：登录接口只支持 POST，浏览器地址栏会得到 **405 Method Not Allowed**，这是正常现象，说明反代已通。

**不要指望外网直接打开** `IP:8000/docs`：生产安全组通常未放行 8000。

## 11. 实战问题速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `docker compose pull` / `i/o timeout` 访问 `registry-1.docker.io` | 国内访问 Docker Hub 超时 | 配 `/etc/docker/daemon.json` 镜像加速后 `restart docker` |
| `poetry install` → `files.pythonhosted.org` ReadTimeout | 官方 PyPI 慢 | Poetry 换清华/阿里源 + 加大 `POETRY_REQUESTS_TIMEOUT` |
| Poetry / 运行报 Python 版本不符 | 用了 3.10 | `poetry env use python3.12` |
| Alembic：`Access denied for user 'admin'@'...'` | `.env` 仍是示例 `admin/admin`，与 Compose 的 `zhongji` 不一致 | 对齐 `MYSQL_*` / `DATABASE_URL` 与 Compose |
| Worker：`DB index is out of range` | `REDIS_URL` 写成 `.../6379` 或 `.../16379`（把端口当成库号） | 改为 `redis://127.0.0.1:6379/0` |
| Worker `activating (auto-restart)` | Redis/库连不上等启动失败 | `journalctl -u zhongji-chat-worker -n 80 --no-pager` |
| 外网 `ERR_CONNECTION_CLOSED` | 云防火墙未放行 80/443，或 Nginx 未 listen | 控制台放行 + `ss -lntp \| grep :80` + `curl http://127.0.0.1/` |
| 登录页「无法连接后端」+ Network 有 `preflight` failed | 前端请求了 `:8000` 或 `https` | `NEXT_PUBLIC_API_BASE_URL=http://公网IP` 后 **重新 build** |
| 本机 `curl 127.0.0.1/api/.../login` 成功，浏览器仍失败 | 同上：浏览器仍用旧打包地址 | 强刷 + 核对 Network 里 Request URL |
| 地址栏打开 login 返回 `{"detail":"Method Not Allowed"}` | GET 调了仅 POST 的接口 | 属正常；用前端登录或 curl -X POST |
| 登录后白屏：`Application error: a client-side exception` | 无窑炉数据时 overview 缺字段导致前端崩溃（已修） | 拉取含修复的前后端代码并重启/重建；可选导入 Excel |
| API 日志出现 `WatchFiles` / reloader | `DEBUG=true` | 生产设 `DEBUG=false` 后重启 API |

查看日志：

```bash
sudo journalctl -u zhongji-api -n 80 --no-pager
sudo journalctl -u zhongji-chat-worker -n 80 --no-pager
sudo journalctl -u zhongji-web -n 80 --no-pager
sudo tail -50 /var/log/nginx/error.log
```

## 12. 推荐实施顺序

1. 买机 → 安全组 80/443/22 → SSH → Swap → UFW  
2. Docker + 镜像加速 → 起 MySQL/Redis/Qdrant  
3. Python3.12 / Poetry + 国内源 → 后端 `.env` → migrate → seed → systemd API+Worker  
4. Node/pnpm → 前端 `NEXT_PUBLIC_API_BASE_URL=http://IP` → build → systemd web  
5. Nginx → 本机 curl 验收 → 浏览器登录  
6. （可选）域名 + Certbot → 改 CORS / 前端基址 → 重建前端  
7. 模型管理配置 LLM → 测对话 / 知识库；需要总览真实数据时再导入窑炉 Excel
