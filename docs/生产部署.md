# 生产部署手册（轻量云主机）

| 项 | 内容 |
|---|---|
| 文档版本 | V1.1 |
| 编制依据 | 2026-08 阿里云轻量机实装与排障；前端由 Next.js 切换为 Vue 3 |
| 后端工程 | `zhongjiAgent`（Poetry / FastAPI） |
| 前端工程 | `zhongjivueweb`（Vue 3 + Vite / npm） |
| 参考规格 | 2 核 4G、约 40GB 盘、5Mbps、Ubuntu 22.04/24.04、公网 IP |

> **相对 V1.0 的变更：** 前端由 `aizhongjiweb`（Next.js，`pnpm start` 监听 :5000）改为 `zhongjivueweb`（Vite 构建静态 `dist/`，由 Nginx 直接托管）。**不再需要** `zhongji-web` systemd 服务。

---

## 1. 架构说明

```
浏览器
  → http(s)://公网IP或域名/          Nginx :80/:443
       ├─ /          → 静态文件  /opt/zhongji/zhongjivueweb/dist
       └─ /api/      → FastAPI  127.0.0.1:8000  （含 SSE）

本机仅内部访问：
  MySQL 127.0.0.1:3306
  Redis 127.0.0.1:6379
  Qdrant 127.0.0.1:6333
  API / Worker 不直接对公网暴露（除调试外勿开 8000）
```

| 进程 | 管理方式 | 说明 |
|---|---|---|
| MySQL / Redis / Qdrant | Docker Compose | 基础设施 |
| `zhongji-api` | systemd | 主 API |
| `zhongji-chat-worker` | systemd | 对话 Stream 归档（生产必须单独跑，禁止用 `zhongji-dev`） |
| 前端静态资源 | Nginx `root` | `npm run build` 产出 `dist/`，无 Node 常驻进程 |
| Nginx | systemd | 唯一公网入口 |

**2C4G 注意：** 内存紧张，务必加 **2～4GB Swap**；限制 MySQL `innodb-buffer-pool-size`；不要同机再起 `zhongji-ai/ingest/model` 占位进程。前端改为静态托管后，比旧 Next.js 方案更省内存。

## 2. 服务器初始化

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y curl wget git vim ufw htop unzip ca-certificates gnupg lsb-release

sudo timedatectl set-timezone Asia/Shanghai

# Swap（强烈建议）
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# 防火墙：只放行 SSH / HTTP / HTTPS
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
```

**云控制台（必做）：** 轻量「防火墙」或安全组放行 **TCP 80、443、22**。  
只开系统 `ufw`、控制台未放行 → 外网会出现 `ERR_CONNECTION_CLOSED` / 无法访问。

目录约定：

```bash
sudo mkdir -p /opt/zhongji
sudo chown -R $USER:$USER /opt/zhongji
```

```text
dial tcp ... registry-1.docker.io:443: i/o timeout
```

```bash
sudo mkdir -p /etc/docker
```

## 5. 基础设施（MySQL / Redis / Qdrant）

```bash
mkdir -p /opt/zhongji/infra
cd /opt/zhongji/infra
```

创建 `docker-compose.yml`（端口仅绑定本机，勿对公网暴露）：

```yaml
services:
  mysql:
    image: mysql:8.0
    container_name: zhongji-mysql
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: "换成强密码_Root"
      MYSQL_DATABASE: zhongji_agent
      MYSQL_USER: zhongji
      MYSQL_PASSWORD: "换成强密码_User"
    ports:
      - "127.0.0.1:3306:3306"
    volumes:
      - mysql_data:/var/lib/mysql
    command:
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_unicode_ci
      - --innodb-buffer-pool-size=256M
      - --performance-schema=OFF
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "127.0.0.1", "-uroot", "-p换成强密码_Root"]
      interval: 10s
      timeout: 5s
      retries: 10

  redis:
    image: redis:7-alpine
    container_name: zhongji-redis
    restart: unless-stopped
    ports:
      - "127.0.0.1:6379:6379"
    volumes:
      - redis_data:/data
    command: ["redis-server", "--maxmemory", "128mb", "--maxmemory-policy", "allkeys-lru"]
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 3s
      retries: 10

  qdrant:
    image: qdrant/qdrant:v1.12.5
    container_name: zhongji-qdrant
    restart: unless-stopped
    ports:
      - "127.0.0.1:6333:6333"
      - "127.0.0.1:6334:6334"
    volumes:
      - qdrant_data:/qdrant/storage

volumes:
  mysql_data:
  redis_data:
  qdrant_data:
```

```bash
docker compose up -d
docker compose ps
```

> 开发用 `deploy/docker-compose.yml` 里 Redis 宿主端口是 **16379**；生产建议 **6379**，并保证 `.env` 与之一致。

### 6.3 systemd

先确认虚拟环境路径：`poetry env info -p`（常见为 `/opt/zhongji/zhongjiAgent/.venv`）。

`/etc/systemd/system/zhongji-api.service`：

```ini
[Unit]
Description=Zhongji FastAPI
After=network.target docker.service
Requires=docker.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/zhongji/zhongjiAgent
Environment=PATH=/opt/zhongji/zhongjiAgent/.venv/bin:/usr/bin
EnvironmentFile=/opt/zhongji/zhongjiAgent/.env
ExecStart=/opt/zhongji/zhongjiAgent/.venv/bin/zhongji-api
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

`/etc/systemd/system/zhongji-chat-worker.service`：

```ini
[Unit]
Description=Zhongji Chat Stream Worker
After=network.target docker.service
Requires=docker.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/zhongji/zhongjiAgent
Environment=PATH=/opt/zhongji/zhongjiAgent/.venv/bin:/usr/bin
EnvironmentFile=/opt/zhongji/zhongjiAgent/.env
ExecStart=/opt/zhongji/zhongjiAgent/.venv/bin/zhongji-chat-worker
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now zhongji-api zhongji-chat-worker
sudo systemctl status zhongji-api zhongji-chat-worker --no-pager
```

期望：

- API 日志：`Application startup complete`、`Uvicorn running on ...`
- Worker：`created stream group chat-archiver` / `chat stream consumer started`，且为 `active (running)`（不是 `auto-restart`）

## 7. 前端部署（Vue 3 + Vite）

前端为 SPA：`npm run build` 生成 `/opt/zhongji/zhongjivueweb/dist`，由 Nginx 直接提供静态文件，**不需要** `zhongji-web` systemd。

### 7.1 环境变量（关键）

`VITE_API_BASE_URL` 在 **`npm run build` 时** 打进浏览器端代码。未设置时代码默认 `http://127.0.0.1:8000`，生产必挂。

| 写法 | 结果 |
|---|---|
| `http://公网IP`（推荐，配合 Nginx） | 浏览器请求 `http://IP/api/...`，同源走 80 |
| `http://公网IP:8000` | 跨域 + 公网常拦 8000 → 登录失败 / preflight failed |
| `https://公网IP`（无证书时） | HTTPS 连不上 →「无法连接后端服务」 |
| 留空 / 不写 | 回落到 `127.0.0.1:8000` → 浏览器连用户本机，必失败 |

```bash
cd /opt/zhongji/zhongjivueweb
cat > .env.production <<'EOF'
VITE_API_BASE_URL=http://你的公网IP
EOF
# 有域名且已配 HTTPS 时改为：https://你的域名
```

本地开发用 `.env`（勿与生产混淆）：

```bash
# 开发机示例
VITE_API_BASE_URL=http://127.0.0.1:8000
```

开发时也可依赖 `vite.config.ts` 里对 `/api` 的 proxy；生产只认构建时打进包的 `VITE_API_BASE_URL`。

### 7.2 构建

```bash
cd /opt/zhongji/zhongjivueweb
npm install
npm run build
# 确认存在：dist/index.html
ls -la dist/
```

> 改过 `VITE_*` 后必须重新 `npm run build`，仅 `reload nginx` 无效。

### 7.3 停用旧 Next.js 前端（从 React 迁移时）

若服务器上仍有旧的 `zhongji-web`（监听 :5000）：

```bash
sudo systemctl stop zhongji-web
sudo systemctl disable zhongji-web
# 可选：删除 unit
# sudo rm /etc/systemd/system/zhongji-web.service
sudo systemctl daemon-reload
```

确认 Nginx 已改为托管 Vue `dist`（见第 8 节）后再删旧目录 `/opt/zhongji/aizhongjiweb`。

## 8. Nginx

```bash
sudo apt install -y nginx
```

`/etc/nginx/sites-available/zhongji`：

```nginx
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    server_name 你的公网IP;   # 或域名 / _

    client_max_body_size 50m;

    # Vue 静态资源（History 模式必须 try_files，否则刷新 /login 等会 404）
    root /opt/zhongji/zhongjivueweb/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        # AI 对话 SSE
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
        chunked_transfer_encoding on;
    }

    # 可选：API 文档（仅内网/调试时有用；外网若不想暴露可删掉）
    location /docs {
        proxy_pass http://127.0.0.1:8000/docs;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    location /openapi.json {
        proxy_pass http://127.0.0.1:8000/openapi.json;
        proxy_set_header Host $host;
    }

    location /redoc {
        proxy_pass http://127.0.0.1:8000/redoc;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

```bash
sudo ln -sf /etc/nginx/sites-available/zhongji /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

有域名后配 HTTPS：

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d 你的域名
```

然后把前端 `VITE_API_BASE_URL`、后端 `CORS_ORIGINS` 改为 `https://域名`，**重建前端**并重启 API。

## 9. 验收清单

```bash
# 服务（前端无 zhongji-web）
sudo systemctl status zhongji-api zhongji-chat-worker nginx --no-pager
ss -lntp | grep -E ':80|:8000'
# 不应再依赖 :5000
ls -la /opt/zhongji/zhongjivueweb/dist/index.html
cd /opt/zhongji/infra && docker compose ps

# 本机经 Nginx
curl -s -o /dev/null -w "web:%{http_code}\n" http://127.0.0.1/
curl -s -o /dev/null -w "spa:%{http_code}\n" http://127.0.0.1/login
curl -s -X POST http://127.0.0.1/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"Admin@123456"}'
```

浏览器：

1. 打开 `http://公网IP/login`，Ctrl+F5  
2. F12 → Network → 登录成功时 Request URL 必须是：  
   `http://公网IP/api/v1/auth/login`（无 `:8000`、无错误的 `https`）  
3. 进入首页；无窑炉 Excel 时可提示「暂无窑炉历史数据」，**不应**白屏崩溃  
4. 后台「模型管理」配置 LLM 后测 `/ai-chat`

**不要用地址栏 GET 打开** `/api/v1/auth/login`：登录接口只支持 POST，浏览器地址栏会得到 **405 Method Not Allowed**，这是正常现象，说明反代已通。

**不要指望外网直接打开** `IP:8000/docs`：生产安全组通常未放行 8000。可经 Nginx 访问 `http://公网IP/docs`（若已按第 8 节开放）。

## 10. 日常更新（代码已上传后如何生效）

仅替换服务器上的源码文件**不会**自动对外生效，必须重启后端并重建前端。

### 10.1 后端

```bash
cd /opt/zhongji/zhongjiAgent
# git pull   # 若用 Git；已用 scp/面板上传则可跳过

poetry install
poetry run python -m alembic upgrade head
sudo systemctl restart zhongji-api zhongji-chat-worker
sudo systemctl status zhongji-api zhongji-chat-worker --no-pager
```

| 变更类型 | 需要的操作 |
|---|---|
| 仅 Python 业务代码 | `restart` API / Worker |
| `pyproject.toml` / 依赖变化 | 先 `poetry install` 再 restart |
| 数据库模型 / 迁移 | 先 `alembic upgrade head` 再 restart |
| `.env` / CORS | 改完后 `restart` API（Worker 若读同一文件也一起 restart） |

### 10.2 前端

```bash
cd /opt/zhongji/zhongjivueweb
# git pull   # 若用 Git；已上传则可跳过

# 确认 .env.production 中 VITE_API_BASE_URL 正确
cat .env.production

npm install
npm run build
sudo systemctl reload nginx
```

| 变更类型 | 需要的操作 |
|---|---|
| Vue / 样式 / 业务前端代码 | `npm run build` |
| `VITE_API_BASE_URL` | 改 `.env.production` 后 **必须** 重新 build |
| Nginx 配置 | `sudo nginx -t && sudo systemctl reload nginx` |
| 仅静态资源已 rebuild | 一般 reload nginx 即可；浏览器 **Ctrl+F5** |

### 10.3 一键核对

```bash
curl -s -o /dev/null -w "web:%{http_code}\n" http://127.0.0.1/
curl -s -o /dev/null -w "api:%{http_code}\n" http://127.0.0.1/docs
ls -lt /opt/zhongji/zhongjivueweb/dist | head
```

备份重点：MySQL dump、`storage/`、Qdrant volume、后端 `.env`、前端 `.env.production`。

## 11. 实战问题速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `docker compose pull` / `i/o timeout` 访问 `registry-1.docker.io` | 国内访问 Docker Hub 超时 | 配 `/etc/docker/daemon.json` 镜像加速后 `restart docker` |
| `poetry install` → `files.pythonhosted.org` ReadTimeout | 官方 PyPI 慢 | Poetry 换清华/阿里源 + 加大 `POETRY_REQUESTS_TIMEOUT` |
| Poetry / 运行报 Python 版本不符 | 用了 3.10 | `poetry env use python3.12` |
| Alembic：`Access denied for user 'admin'@'...'` | `.env` 仍是示例 `admin/admin`，与 Compose 的 `zhongji` 不一致 | 对齐 `MYSQL_*` / `DATABASE_URL` 与 Compose |
| Worker：`DB index is out of range` | `REDIS_URL` 写成 `.../6379` 或 `.../16379`（把端口当成库号） | 改为 `redis://127.0.0.1:6379/0` |
| Worker `activating (auto-restart)` | Redis/库连不上等启动失败 | `journalctl -u zhongji-chat-worker -n 80 --no-pager` |
| 外网 `ERR_CONNECTION_CLOSED` | 云防火墙未放行 80/443，或 Nginx 未 listen | 控制台放行 + `ss -lntp \| grep :80` + `curl http://127.0.0.1/` |
| 登录页「无法连接后端」+ Network 有 `preflight` failed | 前端请求了 `:8000`、错误 `https`，或仍是默认 `127.0.0.1:8000` | `.env.production` 设 `VITE_API_BASE_URL=http://公网IP` 后 **重新 build** |
| 本机 `curl 127.0.0.1/api/.../login` 成功，浏览器仍失败 | 浏览器仍用旧打包地址 | 强刷 + 核对 Network 里 Request URL |
| 刷新 `/login` 等路由 404 | Nginx 未配 `try_files`，仍在反代 :5000 | 按第 8 节改为 `root .../dist` + `try_files` |
| 页面仍是旧前端 | 只上传了源码未 `npm run build`，或 Nginx 仍指向旧工程 | rebuild；核对 `root` 路径；停用 `zhongji-web` |
| 地址栏打开 login API 返回 `{"detail":"Method Not Allowed"}` | GET 调了仅 POST 的接口 | 属正常；用前端登录或 curl -X POST |
| 登录后白屏 / 控制台报错 | 无窑炉数据或缺字段、或前后端版本不匹配 | 拉取最新前后端并 restart/rebuild；可选导入 Excel |
| API 日志出现 `WatchFiles` / reloader | `DEBUG=true` | 生产设 `DEBUG=false` 后重启 API |

查看日志：

```bash
sudo journalctl -u zhongji-api -n 80 --no-pager
sudo journalctl -u zhongji-chat-worker -n 80 --no-pager
sudo tail -50 /var/log/nginx/error.log
sudo tail -50 /var/log/nginx/access.log
```

## 12. 推荐实施顺序

1. 买机 → 安全组 80/443/22 → SSH → Swap → UFW  
2. Docker + 镜像加速 → 起 MySQL/Redis/Qdrant

6. （可选）域名 + Certbot → 改 CORS / `VITE_API_BASE_URL` → 重建前端
