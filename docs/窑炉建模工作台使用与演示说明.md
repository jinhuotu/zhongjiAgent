# 窑炉建模工作台使用与演示说明

入口为前端“能耗 → 窑炉机理建模”，地址 `/kiln-cycles`。原页面保留在 `/kiln-cycles/legacy`，新页面右上角可进入。

本版已经打通资料包解析、AI测点建议、数据版本确认、机理候选构建、参数保存与标定、三类任务算法比较、历史知识复用、数值模型组合、导出和场景试算。预测和指标由实际算法计算；AI负责理解资料与引用证据，不生成预测曲线数值。

## 一 建议演示顺序

1. 新建项目，上传包含工况表、设备说明和测点资料的 ZIP。没有现场资料时可以点击“载入合成演示样例”。样例是4温区、4烧嘴、5个合成窑次，明确标为非现场实测。
2. 在“资料解析”选择文件，展示表头、样本及文档原文位置。解析失败或不支持的文件会说明原因。
3. 在“数据确认”核对自动预填的温区和烧嘴数，勾选数据文件，确认字段映射和单位。可点击“AI识别测点与单位”，待任务完成后查看建议，再点击“填入建议并人工确认”。
4. 每个文件视为一个独立窑次；如果一个文件含多个窑次，应先拆分。确认空气和燃气使用相同标况口径，并区分流量空燃比与阀位比。数值换算采用“原值×倍率+偏移”。
5. 保存数据版本后，进入“机理与参数”。点击“AI理解资料并构建机理”，使用当前模型管理中启用的对话模型。也可以明确选择“资料匹配模板”，这条路径不调用大模型，页面会说明。
6. 展示机理卡、公式和原文引用。点击设备图中的机理，右侧查看变量和参数。来源分别标为文档、人工假设、历史参数或训练标定；未测定参数要经用户确认后保存。
7. 分别进入温度、燃气能耗、空燃比任务，设置预测时长、历史窗口和算法参数，运行真实训练。先看验证集曲线和误差，再“选用算法”。更改配置会使旧实验过期，需要重新运行后才能按新配置选型。
8. 温度任务可切换指定温区或有效均温，支持15/30/60分钟预测。能耗任务可切换瞬时流量和评估窗口累计耗气。可隐藏曲线、缩放时间范围、选择窑次；累计量从完整评估数据计算，不从抽样图点反推。
9. 在实验下方展示训练/验证/测试划分、标定方法和参数。点击“将标定参数存为知识版本”，确认后保存，才能把本次效果较好的参数带入后续数据。
10. 进入“知识与版本”，选历史机理。“用于新数据并重新标定”允许训练集更新参数；“保持旧参数进行验证”固定旧值。保存派生版本后再实验，原版本和原结果不覆盖。
11. 在算法页选择相同数据、任务、温区、时长和历史窗口的另一实验，比较机理/融合曲线及同算法误差。比较前应核对实验超参数和是否重新标定，避免把不同实验条件造成的差异归因于机理本身。
12. 在“模型与试算”确认各任务已选算法，生成组合版本。系统读取数值产物并做保存后推理检查，之后可导出JSON数值模型。
13. 设置回放起点及未来温度计划偏移，按保存版本计算。机理和融合算法支持温度/气耗场景响应；纯数据模型不把相关性预测冒充干预效果。空燃比任务不以温度偏移推断最优控制动作。

右上角“演示讲解”提供与页面对应的六步讲稿。

AI引用采用本次文档片段的短编号，由服务端提取原文并绑定真实文件与位置。兼容模型直接返回引文的情况：仅允许对齐空格、换行等排版差异，不接受数值、单位或数学关系的改写。部分引用失败时只排除失败项；没有可核验来源时自动纠正一次，仍失败则不保存候选并提示选择“资料匹配模板”。页面展示已核验和已排除的引用数量。原文引用真实不等于关联解释已经通过工程验证，仍需确认假设与适用范围。

## 二 五种算法如何解释

### 持续值基线

未来预测值保持当前目标值，即 y(t+h)=y(t)。它是复杂算法的比较参照。它可能在平稳工况下很好，不预设复杂算法必然胜出。

### 时序岭回归

输入包含当前目标值、历史窗口的目标统计量、当前温度/燃气/空气/O₂/窑压，以及已知温度设定计划。使用带L2正则化的线性回归，α控制正则化强度。缺失值填补和标准化只从训练集学习。

### 梯度提升回归树桩

先预测训练目标均值，再逐轮用一个二叶回归树拟合剩余误差。每轮选择一个特征及切分点，学习率决定本轮修正幅度；“提升树轮数”和“学习率”实际参与计算。本版为可解释的小型树桩提升实现，不冒称XGBoost或深度神经网络。

### 机理基线

温度采用闭环一阶响应 dT/dt=(T_sp−T)/τ，假设现场温度控制回路已闭合。计算时以当前温度为起点，用预测时长内线性变化的已知设定计划求解。τ以分钟配置，求解时统一换算时间单位。

燃气流量采用集总热平衡：升温蓄热项加等效损失项，再除以固定的燃气热值及利用效率。升温速率采用预测时长内的平均计划速率。等效热容合并窑体与装载影响；损失系数合并若干热损失，不代表逐项完整热平衡，也不能独立解释每项设备损失。

空燃比的机理参考为理论空气/燃气比乘参考过量空气系数。它用于参考和误差比较，不等于最优操作设定。实际目标始终由同口径空气流量/燃气流量计算；低于燃气有效阈值时不定义实测配比。

### 机理与残差融合

先由机理预测，再以岭回归拟合训练数据中“实测减机理”的残差。最终预测是两者之和。模型产物同时保存机理参数与残差权重。

## 三 参数与验证怎样讲清楚

- 温度标定只搜索响应时间常数，使用训练集在1–600分钟内最小化平方误差；锁定后保持原值。
- 气耗标定对等效热容和损失系数做有界最小二乘；热值和效率固定，不把所有参数同时自由拟合。缺乏升温/保温等足够激励时提示不可辨识风险。
- 数据有多个时间分离的文件窑次时，按完整窑次先后划分训练、验证和测试；不足时采用按时间留出，并剔除目标时间跨越划分边界的样本。
- 同窑次时间留出的结果明确标注为探索性验证，不能当作跨窑次泛化能力。
- MAE是平均绝对误差，RMSE对大误差更敏感。温度单位为℃，流量单位为Nm³/h，配比为Nm³/Nm³，三类任务不能混用误差单位。
- 气耗累计指标仅覆盖有效评估时段；不跨窑次、不跨长缺测或无效点积分，不称为完整窑次总量。
- 未来实测温度、燃气和空气不能作为预测起点的已知输入；未来设定计划可以使用，因为它是已知工艺计划。
- 知识库“已记录离线验证”表示保留了实验与指标，不自动代表通过生产验收。
- 模型试算差值不等于已实现节能，不把没有统计校准的带宽称作置信区间。

## 四 当前支持范围

- ZIP内可读取XLS、XLSX、CSV、DOCX、文本PDF、TXT和Markdown；图片接入系统已有OCR配置，未配置时明确报错。
- ZIP内嵌ZIP会递归展开，最多向内展开3层，保留“内层.zip!/目录/文件”的来源路径。各层共享200个文件和300MB累计解压限制，不会因为嵌套而分别重置限制。XLSX、DOCX交给各自解析器，不作为普通ZIP展开。
- 已上传项目可点击“重新解析资料包”处理原始文件，无需重新上传；已有数据、机理和模型版本不覆盖。
- 扫描PDF未实现自动逐页OCR；无文本时提示转换。CAD、RAR、7z等不支持的格式保留并提示。
- 上传总量80MB，各层累计解压上限300MB、200个文件；单个建模数据版本最多20万行，可从解析出的表格选择窑次创建数据版本。大规模生产数据管道不属于本演示版范围。
- 炉压、余热回收可保存为资料候选；本版未接入其动态求解器，不展示伪造预测。
- 当前不提供实际设备控制下发、最优空燃比控制、深度神经网络训练或未经验证的生产精度承诺。
- 资料与模型按账号隔离；知识库可在该账号的不同项目间复用。跨设备结构不兼容时拒绝直接应用。
- 数据、机理、实验和模型分别保存版本；组合中的各任务独立预测，尚未串联。
- 已保存的模型和实验刷新后可恢复；尚未生成组合版本的前端选型需重新选择。

## 五 部署与验证

后端新增迁移0032，更新依赖后执行：

```powershell
$env:PYTHONPATH='packages;apps'
.\venv\Scripts\python.exe -m alembic upgrade head
.\venv\Scripts\python.exe -m api.main
```

Windows环境后端不使用热重载，修改后需重启API。新增依赖为显式numpy和pypdf，依赖锁文件已经同步。

前端在原目录执行 `npm run build`，开发模式沿用5180端口和8800 API代理。

核心测试：

```powershell
$env:PYTHONPATH='packages;apps'
.\venv\Scripts\python.exe -m pytest tests/test_kiln_studio.py tests/test_kiln_cycle.py tests/test_kiln_analysis.py tests/test_kiln_import.py tests/test_kiln_routes.py -q
```

`runs/check_kiln_studio.py`为真实数据库与已配置AI的集成验证，会新建带“合成演示”标识的项目；不更新原始工况表。`runs/check_kiln_studio_ui.cjs`验证实际页面交互，私有临时认证信息与截图保存在忽略版本管理的storage目录，不能作为对外交付资料。
