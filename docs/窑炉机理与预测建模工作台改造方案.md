# 窑炉机理与预测建模工作台改造方案

本文根据当前前后端实现、用户提供的工作台截图，以及《工业燃气窑炉典型设备运维与数字化能碳管理知识库》正文制定。交付范围是修改方案，本次不修改业务实现。

建议将“窑次预测”升级为“窑炉机理与预测建模工作台”。完整流程为：资料包上传 → 数据与资料确认 → 机理构建与标定 → 分任务算法对比 → 组合生成模型 → 回放试算与版本复用。知识库贯穿整个流程。

## 一 当前实现与需求的差距

1. `packages/common/kiln_xls.py` 支持 ZIP，但仅解析 XLS/XLSX，明确跳过图纸、照片和说明书。上传压缩包并不等于解析整个资料包。
2. `packages/common/kiln_predict.py` 中的 similar、data、physics、fusion 都服务于气耗对照，并不是温度、能耗、空燃比三个业务任务各自的算法集合。
3. 当前机理是固定的二参数经验表达式，参数来自历史数据拟合或代码默认值，没有关联本次资料包的文档依据。
4. `packages/common/kiln_analysis.py` 的温度预测是一阶响应基线，不能用选择气耗算法来代表选择温度算法。
5. 当前试算参数主要是未来温度偏移、剩余时长比例。装载量只用于相似窑次匹配，没有参与热负荷响应计算。
6. `apps/api/services/kiln_reports.py` 在计算后调用大模型组织看板。大模型尚未进入资料理解、测点识别和机理构建环节。
7. `KilnAnalysisRun` 保存分析快照，不能替代独立的机理模板、参数集与可执行模型版本。
8. 温区名称及部分显示逻辑固定为六区。当前工况表以窑号和时间作唯一键，上传重叠数据会更新已有点位；不能直接承担新资料包的不可变数据版本管理。

可复用现有登录权限、模型管理、Excel 读取、ECharts、工况回放、气量积分、报告和快照基础，以及知识库中的文档存储、分块、向量检索、OCR 能力。文档解析接入范围与任务编排仍需补齐。

## 二 先明确几个业务概念

- 资料包：一次上传的原始文件集合，保留目录、文件哈希、解析状态和来源。
- 数据集：从资料包提取并经用户确认的时序、测点、批次和工况标签；清洗后产生新版本。
- 机理模板：能量平衡、物料平衡、传热、燃烧配比等关系，包含变量、单位、假设、适用范围和证据。
- 参数集：机理需要的热容、散热系数、燃气热值等具体数值，与机理模板分别版本化。
- 业务任务：预测什么，例如温度、燃气流量、空燃比。
- 算法：如何计算，例如带滞后项的岭回归、梯度提升树、机理动态仿真。
- 实验：固定数据、机理、参数和配置后的一次训练及评估。
- 模型版本：最终选定的数据处理流程、机理版本、参数集、算法及训练产物的完整绑定。

大模型负责理解资料、提出结构化候选关系和解释证据；文件解析器与数值服务负责精确提取、标定、训练和预测。页面“生成机理”指根据资料构建并验证适用关系，不宣称发现新的物理定律。

## 三 六步业务流程

### 1 资料包上传与解析

首期支持 ZIP。包内支持 XLS/XLSX/CSV 工况数据、DOCX、文本型 PDF、TXT；扫描 PDF 和图片走 OCR，能力不可用时明确提示。原生 CAD、无法解密的压缩包、未知格式保留文件并展示原因，不显示解析成功。

上传后先展示目录树及逐文件状态：等待、解析中、成功、需要确认、失败、不支持。阶段进度必须对应实际完成的文件和任务。支持失败项重试，不重跑所有成功项。

处理步骤：

1. 校验文件类型、解压总大小、文件数量、路径及嵌套深度；不执行包内程序或文档宏。
2. 原文件进入资料包存储，记录 archive_id、file_id、相对路径和哈希，防止不同目录同名文件混淆。
3. 表格解析器提取表头、单位和数据概况，大模型结合点表及手册建议列映射。
4. 文档按章节和表格提取，保留段落、表格单元格或已验证页码位置；图片保留 OCR 区域信息。
5. 生成设备档案候选、测点字典、文件关联和待确认冲突。

表格的全量数值不直接交给大模型计算。模型处理结构、摘要和必要样本，确定性解析器处理每一行原始数值。

### 2 数据与设备确认

页面展示四组内容：设备结构、数据字段、数据质量、文档事实。

用户可以设置：设备编号、温区数、烧嘴数、温区与烧嘴关联、测点对应、单位、时间格式、采样间隔、批次边界、缺测处理方式。烧嘴数与温区数是独立字段，不能相互替代。

数据确认应包含：

- 原始列名 → 标准测点 → 温区/设备 → 单位 → 来源文件和 Sheet。
- 设定值、实测值、控制输出分别标记；瞬时流量与累计量分别标记。
- 时间戳时区、重采样策略、重复点和累计表清零处理。
- 温度、燃气、空气、压力、氧含量的覆盖率与缺测时段。
- 燃气和空气流量是否使用相同的标况/工况口径。
- 窑次、产品、装载量、烧成阶段及数据时间范围。

附件有两处必须进入冲突确认：文件名写“4 烧嘴”，正文写“6 个烧嘴、6 个有效温区”；正文同时涉及流量空燃比与控制阀位比例，且部分总量控制文字中的比例方向需要核对。不能将阀位比直接作为实际空气/燃气流量比。

用户确认后生成不可变 DatasetVersion。数据修正或清洗规则变化生成新版本，原始资料和历史实验保持不变。资料中的阈值是来源事实或候选配置，不自动成为当前设备的正式边界。

### 3 机理构建与参数标定

根据资料和数据提出候选机理，先区分“有理论依据”和“当前数据足以计算”。首期建议包括：

1. 分区能量平衡：燃气输入、预热空气显热、区间交换、物料吸热、窑体蓄热、散热和排烟损失。
2. 空燃比与燃烧关系：实际空气/燃气流量比、理论配比、过量空气系数及可用的氧含量辅助关系。
3. 传热与热惯性：等效热容、窑壁及装载换热、分区耦合和温度响应滞后。
4. 炉压与烟气收支：在具备必要容积、流量或可标定动态数据时建立简化关系。
5. 余热回收：具备换热器或助燃风温度时计算预热贡献，缺少数据时列为待补充。
6. 能碳换算：燃气积分、热值换算及配置排放因子；电量缺失时只计算燃气相关部分。

每张机理卡应显示：名称、公式/关系、物理解释、来源片段、变量映射、参数和单位、假设、适用工况、缺失输入、校验结果，以及“启用、编辑、标定、保存到知识库、使用历史版本”。

机理需要明确是整窑控制体还是分区控制体，防止重复计入区间传热。热量与热功率采用一致的时间口径；燃烧效率与不完全燃烧损失的定义不能重复扣减。附件中的公式应作为待检查来源，不能直接变成可执行计算式。

参数逐项显示来源类型：文档给定、测量得到、历史复用、本次标定、人工输入、暂用假设。提供数值、单位、上下界、锁定开关、适用温度区间和备注。缺少信息时显示待补充；允许用户显式接受假设后形成“假设参数试算”版本。

机理状态建议为：候选、待补充、待标定、已验证、停用。已验证必须附带验证数据和适用范围。校验包括结构与量纲、必要测点、参数边界、数值稳定性、约束满足情况及留出数据误差。不能用大模型自评的置信度替代这些证据。

执行层只接受受控机理模板或可校验的表达式结构，不直接执行模型生成的 Python、SQL 或任意表达式。模板之外的候选关系可以展示、编辑和留存，但需要补齐求解实现才能参与训练。

### 4 按业务任务比较算法

任务切换后，目标、算法、参数、图表单位和评估指标一起变化。算法是否可用取决于输入字段、有效窑次数、训练配置和运行环境，不因下拉框中有名称就标为可训练。

温度预测任务：

- 输出：指定温区未来 15/30/60 分钟温度，或剩余计划下的温度轨迹。
- 首期候选：一阶/集总热容动态基线、带滞后特征的岭回归、带滞后特征的梯度提升树。
- 融合候选：机理预测加历史残差修正。需明确残差如何训练、如何外推。
- 参数：历史窗口、预测步长、采样间隔、正则化强度/树深度，以及热容、散热等机理参数。
- 图表：实测、计划设定、各算法预测；切换温区及预测时长；另看残差和分阶段误差。
- 指标：MAE、RMSE、分温区/阶段误差及误差随预测时长变化。

燃气及能耗预测任务：

- 输出：燃气流量 Nm³/h、未来窗口耗气 Nm³、整窑耗气；具备热值、产量和电耗时再扩展热能、单位产品能耗及综合能耗。
- 首期候选：相似窑次基线、回归模型、简化热平衡模型、机理加残差融合。
- 可复用已有四种算法的代码基础，但要标记原有机理为简化经验基线，不能冒充完整热平衡。
- 参数：训练窑次、相似度特征、工艺阶段、热值、热负荷相关参数及算法超参数。
- 图表：瞬时流量、累计耗气、阶段耗气、残差；累计量与瞬时量分图显示。
- 指标：流量 MAE/RMSE、整窑累计误差、分阶段累计误差和有效数据覆盖率。

空燃比预测任务：

- 输出：未来空气/燃气流量比，燃气接近零时显示不可定义；阀位比例另列。
- 首期候选：最近有效值/分阶段基线、带滞后特征的回归、带滞后特征的梯度提升树。
- 若采用分别预测空气与燃气再求比值，应单独标记为派生方案，并评估分母接近零及误差放大的影响。
- 参数：流量有效阈值、历史窗口、阶段划分、特征选择及算法超参数。
- 图表：实测与各算法预测、空气/燃气流量、氧含量辅助曲线；不同单位分轴或分图。
- 指标：有效燃烧区间的配比 MAE/RMSE、无效样本占比及约束违反情况。

“预测空燃比”和“给出最优空燃比建议”必须区分。后者需要目标函数、工艺气氛要求、质量与排放约束及足够响应证据。首期可先做预测和有条件的方案试算，不用相关性回归冒充参数优化能力。

LSTM、Transformer、PINN 可作为后续扩展能力；在未实现或数据不足时明确显示原因。本次不承诺附件中的精度目标已经达到。

算法比较的共同规则：

1. 用同一目标、同一预测时长、同一验证窑次和一致可评估区间比较，显示各算法覆盖率。
2. 按时间和完整窑次隔离训练、验证、最终测试；清洗统计量、插补模型、特征选择和参数标定仅从训练部分学习。
3. 用户据验证集选型；独立测试结果用于最终确认，不能反复据此调参后仍称独立测试。
4. 除已知计划外，不读取预测起点之后的实测输入。温度预测可使用未来设定计划，但不能混入未来实测流量。
5. 窑次不足时明确为探索性回放或未独立验证，不编造精度排名。
6. 参数改动后实验结果标记过期。重新训练/重算后才能用于生成当前模型版本。
7. 置信区间只有具备对应估计与验证方法时才展示；任意百分比带宽不能称为统计置信区间。

### 5 组合生成模型

用户分别确认温度、燃气能耗、空燃比任务的算法，然后进入组合清单。既可生成单任务模型，也可生成包含多个子模型的方案。

组合清单包含：资料包、数据集版本、字段和单位映射、清洗规则、输入输出、各任务算法、机理版本、参数集版本、训练/验证/测试划分、实验记录和适用范围。

机理的作用要明确选择：直接求解、生成特征、约束拟合、作为残差基线、结果校验，或仅作解释。纯数据算法未使用机理参与计算时，界面必须如实显示，不能因为选中了机理卡就标为机理融合。

若子模型串联，例如温度输出进入能耗模型，需要明确数据流并用上游预测而非未来实测开展端到端评估。独立预测模式则分别使用各自已声明的可用输入，避免循环依赖。

生成时启动真实的构建任务：校验清单、训练或标定、保存预处理器与模型权重/求解器配置、验证推理接口、保存指标和产物哈希。训练失败不得只保存配置就显示“模型生成成功”。

模型版本状态：构建中、失败、未独立验证、验证通过、归档。生成结果提供版本号、输入输出、数据来源、机理与参数来源和回放入口。

### 6 回放试算与历史复用

用选定版本回放或试算，顶部始终显示当前数据集、机理版本、参数集、子模型算法和验证状态。

支持比较原计划与调整计划；支持更换历史机理后重新评估。改变装载量、空燃比或风机参数，只有当前模型具备相应输入和响应机制时才允许用于效果试算，否则显示原因。参数输入框不能只改变页面数值却不影响计算。

历史分析快照保持原结果；应用旧版本到新数据是一次新实验，不覆盖旧快照。

## 四 参考截图的界面设计

顶部为项目/资料包名称、设备、六步流程导航、当前版本、任务状态。全流程保留“查看资料来源”和“知识库”入口。

建模工作区采用三栏结构：

- 左栏约 22%：文件目录、数据集和窑次选择、质量问题、输入字段、历史知识库入口。
- 中栏约 50%：设备与机理关系图，以及温度/能耗/空燃比算法曲线工作区。当前步骤决定主要内容，提供切换，不把所有内容挤在同一屏。
- 右栏约 28%：选中节点的详情和参数抽屉，包含输入输出、机理、参数、来源与版本。

底部为统一时间轴、训练/验证/预测时间段和当前任务进度；训练进度与回放时间分别标记。

设备图从资料确认后的设备结构生成：燃气总管、空气总管、烧嘴、温区、排烟、换热器等。边表示物料、能量或信息关系；无法确认的关系标为候选，不生成装饰性的设备连接。

点击节点后，右侧显示：

1. 输入输出：测点、单位、数据来源、当前值或预测值。
2. 关联机理：公式、假设、证据、适用范围和校验状态。
3. 参数设置：数值、来源、范围、锁定和标定。
4. 历史版本：变更、验证记录、应用/回退。

算法区保留勾选曲线、时间缩放、温区与阶段筛选、误差对比、算法详情和“选用此算法”。选用动作固定到实验 ID，不仅保存算法名称。

视觉上沿用现有产品组件，采用深色工业工作区、清晰留白和有限的状态色。优先保证来源、参数、曲线和结论可读，不以设备动画代替业务信息。

## 五 知识库与版本策略

知识库应有四类资产：原始资料、机理模板、参数集、模型与实验记录。向量检索适合查来源和相似知识，结构化数据库负责精确版本、状态、权限和绑定关系。

机理模板保存公式/受控结构、变量、单位、假设、设备类型、适用温度/工艺、引用文件与位置、审阅及验证记录。参数集独立绑定模板版本和标定数据集；同一机理可以有多套不同工况的参数。

每次新生成均写入新草稿，不能覆盖已验证版本。用户可以收藏、标记适用、停用并写原因；这些人工标签与“已通过数据验证”分开显示。

应用历史资产时提供三种明确模式：

1. 沿用旧机理结构，用新训练数据重新标定参数。
2. 固定旧机理和旧参数，在新数据上直接验证，不重新拟合。
3. 新旧机理及参数方案在相同新数据验证划分上比较，用户选用结果。

复用前检查温区结构、燃料、单位、输入测点、温度及装载范围；不兼容项要求映射或阻止使用。参数不能脱离其模板版本单独乱配。

复用的核心原则是：资料来源可追溯、历史资产不被新草稿覆盖、使用旧版本也要说明在新数据上的适用性。

## 六 后端和前端改造落点

### 后端

1. 保留 `kiln_xls.py` 的表格解析能力，新建 archive 资料包服务分派表格、文档、OCR；不要继续把所有文件处理写入 Excel 解析器。
2. 新增设备结构、测点字典及 DatasetVersion。为建模数据建立独立、按数据集隔离的存储，避免直接复用 `(kiln_code, ts)` 的覆盖写入语义；现有实时看板可以继续使用原工况表。
3. 新增机理构建服务，调用现有模型管理配置，输出受 Schema 校验的设备事实、机理候选、变量及引用。文档内容只作数据，不作为系统指令。
4. 新增受控机理注册表与求解器、参数标定服务。参数标定记录训练集、约束、可辨识性及结果，参数无法由现有测点识别时提示锁定或补充信息。
5. 将 `kiln_predict.py` 拆成按任务组织的算法注册表，声明任务、必需输入、超参数、训练、预测、指标及产物格式。
6. 将 `kiln_analysis.py` 的试算请求改为引用模型版本及场景配置；避免查看详情时自动重拟合后改变当前模型。
7. 扩展 `kiln_reports.py`，基于已完成实验解释选型、机理和局限；数值、图表和来源由服务绑定，大模型不生成预测数组。
8. 增加可持久化的后台任务，涵盖解析、OCR、机理提取、标定、训练和构建；支持重试、取消、超时、断点状态与前端刷新恢复。
9. 所有资料、数据、机理、实验和模型产物按现有用户/知识库权限校验，不能只靠无法猜测的 ID 隔离。

建议新增数据实体：ArchivePackage、ArchiveFile、DatasetVersion、EquipmentSchemaVersion、MechanismVersion、ParameterSetVersion、ExperimentRun、ModelBundleVersion、BuildJob。可按现有命名规范调整或合并元数据表，但版本绑定与不可变产物不能省略。

建议接口资源：

- `/kiln-projects`：建模项目与工作台配置。
- `/kiln-archives`、`/{id}/files`、`/{id}/parse`：上传、清单、解析。
- `/kiln-datasets`、`/{id}/confirm`：数据预览和版本确认。
- `/kiln-mechanisms/generate`、`/{id}/calibrate`、`/{id}/validate`：候选构建、标定、验证。
- `/kiln-knowledge/mechanisms`、`/parameter-sets`：检索、保存与历史复用。
- `/kiln-experiments`：启动及查询单任务多算法实验。
- `/kiln-model-bundles`、`/{id}/simulate`：构建模型与场景试算。
- `/kiln-jobs/{id}`：进度、失败原因和恢复。

所有路径使用现有 API 前缀。写操作携带当前输入版本或配置哈希，任务结果返回同一标识，防止旧任务回写到用户已修改的新方案。

## 七 演示版本的实施顺序

第一阶段：打通资料与机理。

- 完成混合资料包解析、来源定位、字段与设备确认、机理候选和参数编辑。
- 完成机理/参数独立保存和历史复用。
- 验收重点：真实 ZIP 中的数据和说明文档都进入流程，公式变量能关联到测点或参数，冲突可确认，旧版本不会被覆盖。

第二阶段：打通三类任务与真实算法比较。

- 每类任务至少实现两个有意义且确实运行的候选算法；具备条件时加入第三种及融合方式。
- 完成一致验证划分、曲线/误差展示、参数调整与重算、按任务手动选型。
- 验收重点：数据不足会说明原因，同一实验可复现，切换算法或参数会得到相应真实结果。

第三阶段：打通最终模型与演示回放。

- 完成模型组合、产物保存、回放试算、历史版本比较、报告导出。
- 用提前校验的样例包演示全链路；准备一次成功解析、一次冲突确认、一次新旧机理比较。
- 耗时训练可展示明确标注的历史实验，并支持现场启动新任务；不得用预设指标伪装现场训练。

后续再扩展深度时序算法、复杂多区耦合、优化控制建议和实时接入。首期范围优先保证每一步输入、计算、结果和版本关系完整。

## 八 建议的完整演示脚本

1. 上传包含工况表、设备说明、测点表和工艺记录的真实 ZIP，查看文件清单及解析状态。
2. 展示自动提取的数据和文档证据，确认温区、烧嘴、单位和空燃比口径。
3. 展示能量平衡、空燃比、热惯性等候选机理，打开来源；对缺失项设置有标识的假设或选用已有参数。
4. 选温度任务，对比两种以上可用算法，切换温区和 15/30/60 分钟时长；在验证集结果上选型。
5. 分别完成能耗和空燃比任务对比，查看各自的曲线、指标和参数。
6. 打开知识库，选择一份历史已验证机理；在同一新数据验证划分上与新方案比较，保存用户选择。
7. 确认机理作用方式和子模型数据流，生成新模型版本。
8. 使用该版本回放或改参数试算，展示实际重算、适用边界和来源；最后打开版本记录与可复现清单。

演示的解释主线是：系统从哪些资料理解设备，识别了哪些数据，为什么采用这些机理，算法如何公平比较，参数如何影响结果，以及新方案不合适时如何复用过去的有效知识。

算法与评估方案为针对本项目的设计建议，不表示当前代码已经具备相关能力或取得任何精度。

- SciPy 的 least_squares 支持参数上下界，可作为受约束参数标定的实现基础：<https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.least_squares.html>。

附件中的设备参数、阈值、方程和精度目标作为待核对资料使用，不视为当前设备已确认事实或本系统已验证能力。
